# 소비신호등

결제하기 전에 가격 하나를 넣으면, 다음 달 생활비가 어떻게 되는지 빨강/초록 신호등으로 보여주는 1인용 웹앱.

- 서비스: https://sobi.seoyoung.dev

카드값이 이미 많이 나온 상태에서 세일·품절임박에 휩쓸리는 순간을 위한 도구다. 결제를 막지 않고, 결제 직전에 "사면 하루 생활비가 얼마로 떨어지는지"를 보여준다. 기획서와 구현 계획은 [docs/README.md](docs/README.md)의 Notion 링크가 정본이다.

## 화면

| 경로 | 화면 | 하는 일 |
| --- | --- | --- |
| `/login` | 비밀번호 | 6자리 숫자(`APP_PIN`). 화면 키패드와 PC 키보드 모두 받는다 |
| `/` | 홈 (N월 지갑) | 이번 주기에 쓸 수 있는 돈, 이번·다음 카드값, 다음 주기 예상 현금, 쇼핑 예산·생활비·비상금, 확정일·미분류 안내. 이번 주기 설정 전이면 같은 자리에서 설정 마법사 |
| `/setup` | 월 설정 | 날짜(월급일·확정일·카드 출금일) → 수입과 지출(고정지출 결제 수단, 이번·다음 카드값) → 예산 나누기 |
| `/card` | 카드값 | 이번 주기 출금 대금(출금일·출금 완료)과 다음 주기 출금 예정 대금(출금일·카드 고정지출 포함 여부) |
| `/check` | 사기 전에 확인 | 가격 입력 → 빨강/초록 → 안 산다 / 그래도 산다 |
| `/history` | 기록 | 월별 아낀 돈·산 돈 합계, 전체/안 샀어요/샀어요 필터 |

## 렌더링: 전부 "정적 셸 + 스트리밍"

Next.js 16 Cache Components 위에서 만든다. 화면 뼈대(프레임·제목·버튼)는 빌드 때 정적 HTML로 만들어 바로 보내고, 세션과 숫자는 같은 응답 안에서 `<Suspense>` 경계 뒤로 스트리밍한다.

| 경로 | 빌드 결과 | 요청마다 읽는 것 |
| --- | --- | --- |
| `/login` | ○ 정적 | 없음 |
| `/` | ◐ 부분 프리렌더 | 세션, 이번 주기 Month·고정지출·카드 대금·판정 합계 |
| `/card` | ◐ 부분 프리렌더 | 세션, 이번·다음 주기 카드 대금 |
| `/setup` | ◐ 부분 프리렌더 | 세션, 이번 주기(없으면 직전 주기) 설정 |
| `/check` | ◐ 부분 프리렌더 | 세션, 현재 쇼핑 가능액 |
| `/history` | ◐ 부분 프리렌더 | 세션, `?ym=` 주기의 판정 기록 |

**데이터 캐시를 쓰지 않는 이유.** 이 앱에서 가장 나쁜 실패는 오래된 카드값으로 초록 신호가 뜨는 것이다. 그래서 `use cache`도, 브라우저에 값을 남기는 `use cache: private`도 쓰지 않는다. 서버 액션이 성공하면 `refresh()`로 현재 화면을 다시 받는다.

**Activity와 리다이렉트.** 데이터를 읽은 뒤 `redirect()` 하는 화면은 그 리다이렉트까지 Activity에 보존된다. 홈이 "이번 주기 설정 없음"으로 `/setup`에 보냈다면, 설정을 저장하고 홈으로 돌아올 때 보존된 리다이렉트가 다시 실행돼 `/setup`으로 튕긴다(실측). 그래서 홈은 리다이렉트하지 않고 같은 자리에서 설정 마법사를 그린다.

**Activity와 최신성.** Cache Components는 떠난 화면을 언마운트하지 않고 숨긴다. `<Link>`로 돌아오면 Next가 데이터를 다시 받지만, 브라우저 뒤로 가기와 백그라운드 복귀는 숨겨 둔 화면을 그대로 보여준다. `RefreshOnVisible`이 이 두 경우에 `router.refresh()`를 부른다. 판정 화면과 카드값 시트처럼 한 번 쓰고 끝나는 상태는 화면이 숨겨질 때 직접 초기화한다.

**인증.** `proxy.ts`는 쿠키 서명만 보고 미로그인을 `/login`으로 보낸다(DB 조회 없음). 실제 검증은 조회 함수(`lib/queries.ts`)와 모든 서버 액션(`withSession`)이 따로 한다. 서버 액션 요청은 proxy를 건너뛰어, 세션이 만료되면 리다이렉트 대신 `UNAUTHORIZED`를 돌려준다.

## 계산식

금액은 전부 원 단위 정수다. 계산은 순수 함수(`lib/cashflow.ts`, `lib/budget.ts`)로, 클라이언트 미리보기와 서버 저장이 같은 코드를 쓴다.
핵심 원칙은 **실제 현금 흐름과 소비 예산을 나누고, 같은 지출을 두 번 빼지 않는 것**이다.

```text
[현금] 이번 주기 현금      = 월급 − 계좌 출금 고정지출(미분류 포함) − (이번 주기에 출금일이 있는 카드 대금 − 그중 준비금)
[현금] 다음 주기 예상 현금 = 월급 − 계좌 출금 고정지출(미분류 포함) − (다음 주기에 출금일이 있는 카드 대금 − 그중 준비금)
[준비금] 카드 결제 준비금  = 앱에서 "산다"로 산 금액. 산 주기의 쇼핑 예산에서 이미 뺐으므로, 그 구매가 들어간 대금이 출금될 때 다시 빼지 않는다

[소비] 쇼핑 예산(raw)      = 이번 주기 현금 − 생활비 − 비상금 − 이번 주기에 "산다"로 산 금액
       지금 생활비         = 생활비 + min(쇼핑 예산 raw, 0)
       하루 생활비         = ⌊지금 생활비 ÷ 주기 일수⌋

판정: 가격 > 쇼핑 예산 → 빨강, 초과액 = 가격 − 쇼핑 예산, 사면 생활비 = 지금 생활비 − 초과액
      아니면        → 초록, 사고 나면 쇼핑 예산 = 쇼핑 예산 − 가격
```

- **주기**는 월급일부터 다음 월급일 전날까지다. 날짜는 전부 KST로 계산한다(`lib/cycle.ts`). 31일 같은 없는 날은 그 달 말일로 당긴다.
- **카드 대금은 출금일 기준**이다. 사용월·청구월과 상관없이, 실제 출금(예정)일이 속한 주기의 현금에서 빠진다(`card_bills.due_date`). 다음 주기 대금은 이번 주기 현금에서 빼지 않는다.
- **카드 고정지출**(통신비·구독 등)은 카드 대금 안에 들어 있으므로 현금에서 따로 빼지 않는다. 다음 대금이 확정 전이라 아직 안 들어 있으면 그 대금에만 한 번 더한다(`includes_card_fixed`).
- **결제 수단 미분류**(기존 데이터)는 계좌 출금으로 계산하고 홈에 분류하라고 알린다. 임의로 카드로 보지 않는다.
- **출금 완료**는 현금 계산에 영향이 없다. 현금은 주기 시작(월급일) 기준이라 이미 빠진 돈을 다시 빼지 않고, "아직 안 빠진 금액"만 따로 보여 준다.
- **"그래도 산다"**는 산 즉시 이번 주기 쇼핑 예산에서 빠지고, 그 금액은 카드 결제 준비금이 된다. 구매가 들어갈 대금은 카드 확정일·출금일로 계산한다(확정일 24·출금일 5면 11/10 사용은 12/5, 11/25 사용은 1/5 출금, `statementDueDate`). 그 대금이 출금되는 주기의 현금에서는 준비금만큼 덜 뺀다. 판정마다 클라이언트가 만든 id를 붙여, 더블탭이나 재시도로 두 번 와도 한 번만 반영된다. 카드 앱 숫자로 대금을 덮어써도 준비금은 구매 기록에서 다시 계산한다.
- **첫 전환 주기(11월)**는 준비금이 없으므로 11/5 대금(지난 사용분)을 이번 월급에서 전부 낸다. 기존 카드 대금을 정리하고, 새 카드 구매부터 준비금 방식이 적용된다.
- **생활비**는 체크카드·계좌로 쓴다고 본다. 생활비를 신용카드로 쓰면 그 금액은 준비금 없이 다음 대금에만 들어간다.
- **카드 확정일**은 예산을 리셋하지 않는다. 다음 카드값을 확인하라고 알릴 뿐이다.
- **가정**: 다음 월급은 이번 월급과 같다고 본다. 현금은 월급일 기준 계산값이며, 실제 통장 잔액을 따로 입력받지 않는다.

## 환경변수

| 이름 | 내용 |
| --- | --- |
| `DATABASE_URL` | Neon Postgres 연결 문자열. Vercel Marketplace 연동 시 자동으로 들어간다 |
| `APP_PIN` | 로그인 PIN. 숫자 6자리만 허용하며, 따옴표나 공백이 섞이면 어떤 PIN도 통과하지 않는다 |
| `SESSION_SECRET` | 세션 쿠키 서명 키. 32자 이상 임의 문자열(`openssl rand -base64 32`). 바꾸면 모든 로그인이 풀린다 |

## 로컬 실행

```bash
cp .env.example .env.local   # 값 채우기
npm install
npm run db:migrate
npm run dev
```

| 스크립트 | 내용 |
| --- | --- |
| `npm test` | vitest (`lib/**/*.test.ts`) |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run db:generate` | `db/schema.ts` 변경을 `drizzle/` 마이그레이션 SQL로 생성 |
| `npm run db:migrate` | 마이그레이션을 DB에 적용 (이미 적용된 것은 건너뜀) |
| `npm run db:smoke` | DB 연결·트랜잭션 확인 |
| `npm run db:check-choose` | 같은 id 로 "그래도 산다"를 여러 번(순차·동시) 보내도 카드값이 한 번만 오르는지 확인. dev DB 전용, 끝나면 되돌림 |

## 배포

- **리전.** Vercel 함수는 `vercel.json`의 `regions`로 싱가포르(`sin1`)에 두고, Neon도 같은 aws-ap-southeast-1을 쓴다. 한 요청 안에서 DB를 여러 번 왕복하므로 둘을 같은 리전에 두는 게 가장 중요하다.
- **DB 마이그레이션.** Vercel은 `build` 대신 `vercel-build`를 실행하고, 여기서 `db:migrate`를 먼저 돌린 뒤 `next build`를 한다. Neon 연동이 미리보기 배포마다 기본 브랜치를 복사해 새 DB 브랜치를 만들기 때문에, 이 단계가 없으면 미리보기 DB에 테이블이 없어 홈이 500을 낸다. `DATABASE_URL`이 없으면 빌드가 실패한다. production DB에도 배포할 때마다 같은 방식으로 적용된다.
- **PWA.** manifest와 아이콘만 둔다(서비스워커 없음). 아이폰은 Safari → 공유 → "홈 화면에 추가". 아이콘 원본은 `public/icons/icon.svg`다.

## 성능 실측

> 아직 재지 않았다. `scripts/measure.mjs`로 production(https://sobi.seoyoung.dev)을 잰 뒤 채운다. 다른 주소는 마지막 인자로 넘긴다.

```bash
CG_SESSION=<sobi.seoyoung.dev 에 로그인한 브라우저의 cg_session 쿠키 값> node scripts/measure.mjs
```

콜드는 10분 이상 아무도 열지 않은 뒤의 첫 요청(함수와 Neon이 모두 깨어나는 시간)이다. 웜은 이어지는 요청 10회의 중앙값이다. "홈 아이콘 → 판정 결과"는 폰 홈 화면 아이콘을 누른 순간부터 가격을 넣고 신호등이 뜰 때까지를 손으로 10번 잰다.
